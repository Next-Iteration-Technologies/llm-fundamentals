Agent Fundamentals & Multi-Agent

Ask the room first, then click to reveal. Definitions are quoted from Anthropic, OpenAI and the MCP project; see Sources.

Part 1 · Agent fundamentals

01What is an agent?

An LLM that decides its own steps and tools to get a task done.

[O]“Agents are systems that independently accomplish tasks on your behalf.”
[A]“Agents … are systems where LLMs dynamically direct their own processes and tool usage, maintaining control over how they accomplish tasks.”
[A]Contrast: “Workflows are systems where LLMs and tools are orchestrated through predefined code paths.”

Examples

  • DASThe Retrieval agent finds nothing for “Meyer Logistics”, so it widens the search and finds “Meyer Log. GmbH”.
  • A coding agent runs the tests, reads the failure, fixes the code and runs the tests again.
  • Not an agent [O]: “simple chatbots, single-turn LLMs, or sentiment classifiers”.
02What is a tool?

A function the model chooses to call. Your code runs it.

[O]“External functions or APIs the agent can use to take action.”
[A-TU]“Claude determines when to call a tool based on the user’s request and the tool’s description. It then returns a structured call that your application runs.”

Examples

  • [O]Three tool types: Data (query a CRM, read PDFs, search the web), Action (send email, update a record), Orchestration (another agent used as a tool).
  • DASsearch_documents and read_policy are data tools.
  • DASNo agent has a delete or send tool, so contract 7001 is safe and the instruction smuggled into record 1236 does nothing.
03What is a skill?

An onboarding guide the agent opens only when it needs it.

[A-SK]“Agent Skills: organized folders of instructions, scripts, and resources that agents can discover and load dynamically to perform better at specific tasks.”
[A-SK]“Building a skill for an agent is like putting together an onboarding guide for a new hire.”

How it loads [A-SK]: only the name and description are loaded at startup. The full SKILL.md and its extra files are read only when relevant (“progressive disclosure”).

Examples

  • [A-SK]A PDF skill with form-filling instructions and a Python script that extracts form fields.
  • DASA “tax-audit export” skill holding the checklist, naming rules and who to notify.
  • Contrast: send_email is a tool; “how we write escalation emails” is a skill.
04What is the agent loop?

Gather context, take action, verify, repeat until an exit condition is met.

[A]Agents “are typically just LLMs using tools based on environmental feedback in a loop.”
[A-SDK]“gather context → take action → verify work → repeat.”
[O]“a loop that lets agents operate until an exit condition is reached. Common exit conditions include tool calls, a certain structured output, errors, or reaching a maximum number of turns.”

Examples

  • DASRetrieval makes 7 searches, each one based on the previous result.
  • DASPolicy reads the policy, then the emails, then finds the Legal hold.
  • [A]Agents get “ground truth” at each step from tool results or code execution, and use “stopping conditions (such as a maximum number of iterations)”.
05What is MCP?

A USB-C port for AI. You build the connector once and every agent can use it.

[MCP]“MCP (Model Context Protocol) is an open-source standard for connecting AI applications to external systems.”
[MCP]“Think of MCP like a USB-C port for AI applications.”

Examples

  • [MCP]Agents can access Google Calendar and Notion; Claude Code can build a web app from a Figma design.
  • [MCP]The same server works in Claude, ChatGPT, VS Code and Cursor.
  • DASsearch_documents could be served as an MCP server. MCP doesn’t choose which tool to call; the agent does.
06What is the agent stack?

Model + instructions + tools + knowledge/memory, wrapped in orchestration and guardrails.

[O]An agent “consists of three core components:” Model, Tools, Instructions, plus Orchestration and Guardrails.
[A]“The basic building block of agentic systems is an LLM enhanced with augmentations such as retrieval, tools, and memory.” (the augmented LLM)

Synthesis: no standard source defines an “agent stack” by that name. This combines the closest official definitions.

Part 2 · Multi-agent

07What is multi-agent?

Several agents, each running its own loop, working together on one task.

[A-MA]“A multi-agent system consists of multiple agents (LLMs autonomously using tools in a loop) working together.”
[O]“workflow execution is distributed across multiple coordinated agents.”

Examples

  • [A-MA]Claude Research: a lead agent spawns parallel search subagents, then a CitationAgent.
  • [O]A triage agent hands off to an order-management agent or a technical-support agent.
  • DASIntake → Retrieval → Policy → Access & Action (code) → Responder.
08What is an agent boundary?

Objective, output format, tools, and clear limits.

[A-MA]“Each subagent needs an objective, an output format, guidance on the tools and sources to use, and clear task boundaries. Without detailed task descriptions, agents duplicate work, leave gaps, or fail to find necessary information.”
[O]An agent uses tools “always operating within clearly defined guardrails.”

Synthesis: no standard source defines “agent boundary” as a term. These are the closest official statements.

Examples

  • DASRetrieval is read-only, Policy advises but never grants, and the Responder has no tools.
  • DASAn unclear boundary made Policy treat “Classic” as a policy issue.
  • [A-MA]Without clear boundaries, agents duplicate work or leave gaps.
09When should you go multi-agent?

Start with one agent. Split for complex logic, tool overload, parallel work or context limits.

[O]“maximize a single agent’s capabilities first … often a single agent with tools is sufficient.”
[O]When to split: Complex logic (many if-then-else branches in one prompt) and Tool overload: “some … manage more than 15 well-defined, distinct tools while others struggle with fewer than 10 overlapping tools.”
[A-MA]Multi-agent excels at “heavy parallelization, information that exceeds single context windows, and interfacing with numerous complex tools.”
[A-MA]Cost: “multi-agent systems use about 15× more tokens than chats.” A poor fit when agents must share the same context or depend heavily on each other.
[A]“find the simplest solution possible, and only increase complexity when needed.”

Examples

  • [A-MA]Finding the board members of every IT company in the S&P 500: the multi-agent system succeeded where the single agent failed.
  • [A-MA]Poor fit: most coding tasks, which have few truly parallel parts.
  • DASWith 7 records and 1 policy, a single agent would do. Split for scale, ownership or audit.
10What are the multi-agent patterns?

Chain, route, parallelize, orchestrate, evaluate; or manager vs. handoff.

Anthropic workflow patterns [A]

  • Prompt chaining: steps run in sequence.
  • Routing: “classifies an input and directs it to a specialized followup task.”
  • Parallelization: sectioning (independent subtasks) or voting (same task several times).
  • Orchestrator-workers: “a central LLM dynamically breaks down tasks, delegates them to worker LLMs, and synthesizes their results.”
  • Evaluator-optimizer: “one LLM call generates a response while another provides evaluation and feedback in a loop.”

OpenAI multi-agent patterns [O]

  • Manager (agents as tools): “A central ‘manager’ agent coordinates multiple specialized agents via tool calls.”
  • Decentralized (agents handing off to agents): “Multiple agents operate as peers, handing off tasks to one another.”

11What is a sequential pipeline?

Fixed steps in order, each one taking the last one’s output, with code gates in between.

[A]“Prompt chaining decomposes a task into a sequence of steps, where each LLM call processes the output of the previous one. You can add programmatic checks (see ‘gate’ in the diagram below) on any intermediate steps.”
[A]When to use: “the task can be easily and cleanly decomposed into fixed subtasks. The main goal is to trade off latency for higher accuracy, by making each LLM call an easier task.”

Examples

  • [A]Write marketing copy, then translate it.
  • [A]Write an outline, check it against criteria, then write the document.
  • DASIntake → Retrieval → Policy → gate: Access & Action (code) → Responder.

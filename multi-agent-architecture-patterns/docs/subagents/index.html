Multi-agent patterns · Concept

A subagent is the same loop in a different seat

Under the hood both are a model, a set of tools and a loop that runs until the model decides it's done. What makes one a subagent is who it works for. The second half covers how an orchestrator runs its subagents: in parallel or in sequence, by handoff or as tools, and what the industry calls each part.

Standalone agent

Works for a person. Owns the whole goal, sees the whole conversation, and can stop and ask.

Subagent

Works for another agent. Gets one task like a function call, hands one result back, then it's gone.

What it looks like

Briefs go down, short results come up, and the heavy reading stays below

The three subagents run at the same time. The orchestrator gets three paragraphs back instead of 40 files, 12,000 log lines and 9 pages. That gap is the main reason to split the work.

Five things that change in the subagent seat

What a subagent lives with

It starts knowing nothing

All it has is the brief. "Check the auth code" with no reason means it has to guess what you're after.

Most subagent failures come from thin briefs, not weak models.

Another model reads its output

Its reader is the parent agent, not a person. A friendly essay just costs the parent tokens to parse.

Ask for findings, evidence and a confidence level.

It can't ask anyone

Nobody is on the other end to answer a question, so it has to pick a reading of the task.

Tell it what to do when it's unsure: guess and say so, or stop.

It's short-lived

It's created for one task and thrown away when that task is done. Anything it learned and didn't report is lost.

Whatever the parent needs later has to be in the result.

Its tools are narrowed

A search agent gets read access only. A reviewer can't edit files.

A narrower toolset makes it more focused and safer to run.

The handoff is the whole job

The same task, briefed two ways

Write the brief as if the reader had walked in mid-meeting. Include the goal, what you already know, where to look, what shape to send back, and when to stop.

Why split at all

Three reasons to hand work to a subagent

Usually the real reason

Isolation

The subagent does the messy reading, and the parent's context stays clean. You keep the conclusion, not the file dumps.

Parallel work

Five independent searches can run at once, each in its own subagent, instead of one after another.

Focus

A narrow job with a narrow toolset gets done more reliably than one more item on a long to-do list.

What you pay

Every handoff costs something

Tokens

Each subagent re-reads its own instructions and does its own exploring. Three subagents can cost several times what one agent would.

Lost context

Whatever the parent leaves out of the brief, the subagent doesn't know. Nuance gets lost at every handoff.

Unchecked results

The parent only sees the summary. If a subagent invents a finding, the parent can't tell unless something checks it.

This is why the hardened Pattern 01b adds typed handoffs (results must match a schema) and a grounding check (claims must point at real evidence). They exist to cover these weaknesses.

Orchestration · parallel or sequential

Subagents aren't parallel or sequential. The dependencies decide.

Ask one question: does the next step need this result? If it does, the step waits. If it doesn't, run them at the same time.

Parallel cuts the wait

Three research subagents take as long as the slowest one, not as long as all three added together.

Background doesn't remove the wait

The orchestrator can do unrelated work while a subagent runs, but anything that uses the result still waits for it.

Use a handoff when

One specialist should own the rest of the conversation. Triage sends you to Billing, and Billing takes it from there.

Use a manager when

The answer needs several specialists combined, checked, or kept in one voice, like research or the 01b audit request.

Not the same as 01b

In the 01b pipeline, code fixes the order. In a relay, the agent decides who's next. That makes it more flexible and harder to test.

Agents as tools are subagents. A handoff changes seats: the agent that receives it becomes the standalone agent, because it now owns the user and the goal.

In this course

Orchestrator for the role. Parent / subagent for the relationship. Read manager and supervisor as synonyms when you meet them in other docs.

Careful

A coordinator is sometimes a pure router. It dispatches and never combines results, which makes it closer to a handoff than to a manager.

One line to remember
Standalone agent = employee

Talks to the client, knows the history, can ask questions and decides when the job is done.

Subagent = contractor

Gets a work order, can't call the client, and sends back a report.

Any standalone agent becomes a subagent the moment another agent calls it as a tool.

Basic words we will use today

AI app

The product you click on: ChatGPT, Claude, Cursor. It picks a model and adds tools.

Model (LLM)

The trained system inside the app. It writes one small piece at a time.

Token

A small piece of text. You pay per token, for input and for output.

Context window

How much text the model can look at in one request. Top models: about 1 million tokens.

Thinking (effort)

Hidden steps before the answer. Low, medium or high. Billed as output.

Agent

The model uses tools, such as tests, files and search, over many steps.

2.2 Part 2 · How AI models are tested and compared

Three ways a test can be marked

Exact answer

One right letter or number. A script checks it.

Cheap and fair. Works only for closed questions.

Tests must pass

The code change runs against unit tests.

Close to how we judge code. Only as good as the tests.

Judged

People vote, or a strong model marks it against a checklist.

Good for open answers. Judges can like long answers.

Seven questions for the next launch post.

  • Who ran it?

Three common problems with tests: too easy, leaked, broken

Too easy

"saturated"

Everyone scores in the mid-90s. The last mistakes are often errors in the test.

Leaked

"contamination"

The model saw the questions in training, like seeing the exam paper the night before.

Broken

bad tasks

Tests reject a correct fix, or the task leaves out a requirement.

5.5 Part 5 · Running AI models on our own machines

What fine-tuning is

You take a model you already have and train it a little more on your own examples.

The aim is a habit the model should keep: a fixed format, a house writing style, or a steady way of calling a tool.

A plain example

An internal policy assistant should give a short answer, then end with a small JSON block.

{"policy_id": "HR-14", "escalation_needed": false}

Where the facts live

Policy facts, such as how many leave days staff get, stay in your documents. The system looks them up when someone asks. That lookup is called RAG.

When to use a prompt, RAG, or fine-tuning

Start with a clear prompt. Add RAG for facts that change. Fine-tune for format, tone, and habits.

Prompting

Task instructions you can write in the prompt.

"Reply in three bullets."

RAG

Facts that change or live in files. The system searches and pastes the useful excerpts into the prompt.

Leave policy, prices, tickets, repo files

Fine-tuning

Format, tone, and habits the model should keep.

Always end with a JSON footer, or write tests in your team's style

You can use both: the model keeps the habit, and RAG supplies the current facts.

5.8 Part 5 · Running AI models on our own machines

What a training file looks like

A JSONL file: one JSON object per line, each line one example.

train.jsonl
{ "messages": [ { "role": "system", "content": "You are an internal policy assistant. End every reply with a JSON object." }, { "role": "user", "content": "How many days of paternity leave do employees get?" }, { "role": "assistant", "content": "Eligible employees receive 10 working days.\n\n{\"policy_id\": \"HR-14\", \"escalation_needed\": false}" } ] }

Keep a separate test file the trainer never sees, so you can check whether the habit improved.

Questions people may ask

Should we fine-tune our own model?

Later. Start with a good prompt, a mid-size model, search over our docs and a golden set.

How is a model frozen?

Training stops, a fixed copy gets a name, and it learns nothing after its cutoff.

Which model is number one?

It depends on the job. Open today's Arena or Artificial Analysis board.

DeepSeek for everything?

Great price. Test it first, and check the client's data rules.

Are open models as good as Claude?

Close on everyday work. Still behind on the hardest agent work.
